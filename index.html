Modelado de Procesos

Diagramas, herramientas CASE y el arte de comunicar sistemas 🎨

¿Por qué modelar procesos?

🧠 Claridad

Un buen diagrama comunica un proceso complejo en segundos. Mucho mejor que 10 páginas de texto.

🔍 Análisis

Permite identificar cuellos de botella, pasos redundantes y oportunidades de mejora.

📚 Documentación

Sirve como referencia para el equipo de desarrollo y para futuras mantenciones.

🗣️ Comunicación

Es un lenguaje común entre usuarios, analistas y desarrolladores. Todos ven lo mismo.

Tipos de diagramas

📊 Diagrama de Flujo

▼

El más básico y universal. Representa un proceso como una secuencia de pasos, decisiones y resultados.

🔵 Inicio
↓
📋 Recibir solicitud
↓
🔶 ¿Datos completos?
⬅️ No → Solicitar Sí ⬇️
🟢 Fin
  • Símbolos: Óvalo (inicio/fin), rectángulo (proceso), rombo (decisión), flecha (flujo).
  • Uso: Procesos simples, algoritmos, flujos de trabajo.

🔄 DFD (Diagrama de Flujo de Datos)

▼

Muestra cómo se mueven los datos a través de un sistema: entradas, procesos, almacenes y salidas.

👤 Usuario
↓
⚙️ Proceso: Validar pedido
↓
💾 Almacén: Base de datos
  • Símbolos: Entidad externa (rectángulo), proceso (círculo/óvalo), almacén (rectángulo abierto), flujo (flecha).
  • Uso: Sistemas de información, análisis estructurado (Kendall & Kendall).

🎯 UML - Diagrama de Actividades

▼

Similar al diagrama de flujo pero con notación UML estándar. Incluye swimlanes (carriles) para mostrar responsabilidades.

👤 Usuario
→ Solicitar turno
⚙️ Sistema
→ Validar disponibilidad
👨‍⚕️ Médico
→ Confirmar turno
  • Ventaja: Muestra quién hace qué (swimlanes).
  • Uso: Modelado de casos de uso, flujos complejos con múltiples actores.

📋 BPMN

▼

Business Process Model and Notation. Estándar para modelar procesos de negocio con notación rigurosa.

↓
📝 Recibir pedido
↓
↓
  • Símbolos: Eventos (círculos), actividades (rectángulos redondeados), puertas de enlace (rombos).
  • Uso: Procesos de negocio, integración TI-negocio.

¿Cuál usar?

📊 Diagrama de Flujo

Cuando el proceso es simple y el público no es técnico. Es el más fácil de entender.

🔄 DFD

Cuando necesitás mostrar cómo viajan los datos en un sistema de información. Clásico del análisis estructurado.

🎯 UML Actividades

Cuando hay múltiples actores y necesitás mostrar responsabilidades con swimlanes.

📋 BPMN

Cuando el proceso es de negocio y necesitás un estándar riguroso para documentación formal.

Herramientas CASE

Las herramientas CASE (Computer-Aided Software Engineering) son programas que asisten en las actividades de ingeniería de software. Su objetivo es automatizar tareas, mejorar la productividad y asegurar consistencia.

🎨 draw.io

Gratuita, web, sin instalación. Ideal para diagramas de flujo, UML, DFD y más. La usaremos hoy.

🤖 Mermaid + IA

Genera diagramas a partir de texto. Combinado con IA, podés describir un proceso y obtener el diagrama listo.

📋 Jira

Para gestión de proyectos. Ya lo usaron en la clase anterior.

🎨 Figma / Uizard

Para prototipos de interfaz. Ya lo usaron en la clase anterior.

Desafío: Modelado de Procesos

Trabajen en tríos o pares. Elijan uno de los escenarios de la clase anterior y modelen su proceso.

📌 Importante: Vamos a usar draw.io para crear los diagramas. Es gratuita, no requiere instalación y funciona en el navegador. También pueden usar Mermaid con IA si prefieren generar el diagrama a partir de texto.

🏥 Sistema de Turnos Médicos

Modelen el proceso completo: desde que el paciente solicita un turno hasta que el médico lo confirma.

1

Identificar el Proceso a Modelar (10 min)

Elijan uno de los escenarios y definan qué proceso van a modelar. Escriban en una hoja o documento:

  • Nombre del proceso.
  • ¿Dónde empieza? (evento de inicio)
  • ¿Dónde termina? (evento de fin)
  • ¿Qué actores participan?
Análisis
2

Elegir el Tipo de Diagrama (5 min)

Según el proceso elegido, decidan qué notación usar:

  • Diagrama de Flujo: Si es un proceso simple, lineal, con pocas decisiones.
  • DFD: Si quieren mostrar cómo viajan los datos (entradas, procesos, almacenes, salidas).
  • UML Actividades: Si hay múltiples actores con responsabilidades claras (usar swimlanes).
Decisión Justificación
3

Crear el Diagrama en draw.io (20 min)

Abran app.diagrams.net y sigan estos pasos:

draw.io
📋 Instrucciones APB:
  1. Hagan clic en "Crear nuevo diagrama" → "Blank Diagram".
  2. En el panel izquierdo, busquen las formas. Para Diagrama de Flujo: usen óvalos (inicio/fin), rectángulos (procesos), rombos (decisiones) y flechas.
  3. Para DFD: usen rectángulos (entidades), círculos (procesos), rectángulos abiertos (almacenes) y flechas.
  4. Para UML Actividades: usen los swimlanes (carriles) para separar actores. Arrastren el swimlane y ajusten el número de carriles.
  5. Mínimo 5 elementos, máximo 12. No busquen la perfección, busquen comunicar el proceso.
  6. Exporten como PNG (Archivo → Exportar como → PNG) y guárdenlo.
4

Alternativa: Generar con IA (10 min)

Si prefieren una opción más rápida, usen Mermaid con IA. Pueden pegar este prompt en cualquier chatbot:

Mermaid + IA
Prompt para IA (copiar y pegar):
"Genera un diagrama de flujo en formato Mermaid para el proceso de [PROCESO]. El diagrama debe mostrar: inicio, los pasos principales, las decisiones, y el fin. Usa la sintaxis Mermaid estándar."

Luego: Copien el código Mermaid generado y péguenlo en mermaid.live para ver el diagrama. Exporten como PNG.
5

Presentación y Justificación (10 min)

Cada trío tendrá 3 minutos para presentar:

  • El proceso que modelaron.
  • La notación elegida y por qué.
  • El diagrama final (mostrar en pantalla).
  • Una reflexión: ¿Qué aprendieron al modelar el proceso? ¿Qué harían diferente?
